# Going live — BRG Prime API

This guide takes the backend from local (SQLite) to a **live** deployment on
**Render**, with **Neon Postgres**, **Resend** email, **Cloudflare R2** uploads,
and **real Paystack** payments.

Work top to bottom. Each section lists exactly what to click and which value to copy.

---

## 0. Prerequisites
- A GitHub account (Render deploys from a Git repo).
- This folder pushed to a GitHub repo:
  ```bash
  cd BRG-Prime-Backend
  git init && git add . && git commit -m "BRG Prime API"
  # create an empty repo on github.com, then:
  git remote add origin https://github.com/<you>/brg-prime-backend.git
  git push -u origin main
  ```
  `.env`, `node_modules`, and `prisma/dev.db` are git-ignored — good.

---

## 1. Database — Neon Postgres  ➜ `DATABASE_URL`
1. Go to <https://neon.tech> → sign up (free) → **Create project** (region: EU/Frankfurt is closest to Nigeria).
2. On the project dashboard, copy the **Pooled connection string**. It looks like:
   `postgresql://user:pass@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require`
3. Keep it — you'll paste it as `DATABASE_URL` in Render (and locally to run the first migration).

**Switch the project to Postgres and create the schema** (run locally once):
```bash
npm run use:postgres                 # flips schema provider to postgresql
# temporarily set DATABASE_URL in your .env to the Neon string, then:
rm -rf prisma/migrations             # drop the SQLite-flavoured migrations
npx prisma migrate dev --name init   # creates Postgres migrations against Neon
npm run db:seed                      # seed the mock data into Neon
git add -A && git commit -m "Postgres migrations" && git push
```
> To go back to local SQLite later: `npm run use:sqlite` and restore the SQLite `DATABASE_URL`.

---

## 2. Email — Resend  ➜ `RESEND_API_KEY`, `EMAIL_FROM`
1. <https://resend.com> → sign up → **API Keys** → **Create API Key** → copy it (`re_...`).
2. **Domains**: to send from `@brgprime.ng`, add the domain and its DNS records.
   Until then use the sandbox sender: `EMAIL_FROM="BRG Prime <onboarding@resend.dev>"`.
3. Set `OTP_RETURN_IN_RESPONSE=false` in production so codes are only emailed.

---

## 3. Uploads — Cloudflare R2  ➜ `R2_*`
1. Cloudflare dashboard → **R2** → **Create bucket** (e.g. `brg-prime`).
2. **Manage R2 API Tokens** → **Create API token** (Object Read & Write) →
   copy **Access Key ID** and **Secret Access Key**.
3. Your **Account ID** is on the R2 overview page → `R2_ACCOUNT_ID`.
4. Bucket → **Settings** → enable **Public access** (R2.dev URL) or attach a custom
   domain. Copy that base URL → `R2_PUBLIC_URL` (e.g. `https://pub-xxxx.r2.dev`).

Values: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_URL`.

---

## 4. Payments — Paystack  ➜ `PAYSTACK_*`
1. <https://dashboard.paystack.com> → sign up → **Settings → API Keys & Webhooks**.
2. Copy the **Test Secret Key** (`sk_test_...`) and **Test Public Key** (`pk_test_...`).
   (Switch to live keys when you're ready to take real money.)
3. Set `PAYSTACK_CALLBACK_URL` to your web app's subscriptions page, e.g.
   `https://your-web-app.vercel.app/subscriptions`.
4. **Webhook URL** (same settings page): set it to
   `https://<your-render-app>.onrender.com/api/payments/paystack/webhook`.
   The server verifies the `x-paystack-signature`, so only genuine Paystack calls activate plans.

---

## 5. Deploy — Render
1. Push the repo to GitHub (step 0).
2. <https://render.com> → **New → Blueprint** → pick the repo. Render reads `render.yaml`.
   (Or **New → Web Service** with build `npm ci && npx prisma generate && npx prisma migrate deploy`
   and start `node src/server.js`.)
3. In the service **Environment**, fill every `sync:false` value:
   `DATABASE_URL`, `APP_URL` (your Render URL), `WEB_URL`, `CORS_ORIGIN`,
   `RESEND_API_KEY`, `EMAIL_FROM`, all `PAYSTACK_*`, all `R2_*`.
   `JWT_SECRET` is auto-generated by Render.
4. Deploy. Watch the logs for `🏠 BRG Prime API running`.
5. Verify: open `https://<your-app>.onrender.com/` → should return the health JSON.

> **Note (free plan):** Render free web services sleep after inactivity and cold-start
> in ~30–60s. Fine for testing; upgrade to a paid instance for production.

---

## 6. Point the apps at the live API
- **Web:** set the API base URL to `https://<your-app>.onrender.com/api`.
- **Mobile:** same base URL for a real device; use `http://10.0.2.2:4000/api` only for the local Android emulator.
- Add each app's origin to `CORS_ORIGIN`.

## Secrets checklist (paste these into Render)

| Variable | From |
|---|---|
| `DATABASE_URL` | Neon pooled connection string |
| `RESEND_API_KEY` | Resend → API Keys |
| `EMAIL_FROM` | `BRG Prime <onboarding@resend.dev>` (or your domain) |
| `PAYSTACK_SECRET_KEY` / `PAYSTACK_PUBLIC_KEY` | Paystack → API Keys |
| `PAYSTACK_CALLBACK_URL` | your web `/subscriptions` URL |
| `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` / `R2_PUBLIC_URL` | Cloudflare R2 |
| `APP_URL` / `WEB_URL` / `CORS_ORIGIN` | your deployed URLs |
